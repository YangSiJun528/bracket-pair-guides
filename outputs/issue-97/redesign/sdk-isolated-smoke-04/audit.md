## Limits before formal comparison

The same inputs/shared code do not make baseline and candidate orchestration identical: direct adapters include their own setup overhead; baseline MAIN daemon-driven full refresh is outside the owned edit fixture while candidate full refresh is factory-owned. Neither explicit headless ACTIVE nor native resolver success proves actual Swing focus, daemon orchestration, or paint. Formal six-JVM-pair analysis must preserve those distinctions, all writer misses/censored outcomes, and separated allocation scopes. This audit makes no timing, allocation-regression, or universal leak-freedom conclusion.
