# Indentation edit geometry proof

## Cause and narrow change

Before this change every edit inside a multiline pair drops its guide even when the minimum indentation is unchanged. Actual EditorTab/EditorUnindentSelection commonly normalize12→16→12 spaces as edits at logical column12 while closing indentation and guide column remain8. The new presentation proof may retain existing geometry only for bounded horizontal-whitespace events starting strictly to the right of the current minimum. Core/runtime/model/build contracts are unchanged.

DocumentChange.from(DocumentEvent) first checks oldLength+newLength<=256 using long arithmetic, then visits the original old/new CharSequences for ASCII space/tab only. It copies no fragments and retains no event/CharSequence. Existing manually constructed DocumentChange values default to unknown, preserving their former conservative behavior. EditorGuideEvents captures these facts only after the preview guard and attached-editor early return, avoiding classification for unrelated unowned documents.

GuidePositionFallback retains existing same-line/outside-pair behavior. For an inside-pair edit it additionally requires existing previous geometry and whitespace facts, bounds the mapping physical prefix to4096 characters using SDK line metadata, then asks offsetToLogicalPosition(offset).column>G. No document prefix, indentation, token or PSI scan and no new minimum calculation occurs in UI. The physical-prefix cap is a conservative optimization admission limit; longer prefixes use the old hide+repair behavior. It is not a change to core repair or recognition limits.

## Proof and bounds

The unchanged prefix before event.offset gives the same start logical column after the edit. If first content was before that column, indentation is unchanged. Otherwise a horizontal-whitespace-only replacement cannot bring first content before the edit start, which is strictly greater thanG. Blank lines remain blank. No edited line can acquire or lose the earliest minimumG anchor, so current guideColumn/anchor remain valid and existing SDK pair/anchor markers track offset shifts. Visual columns are not used because soft wraps can reset them. Inductive preservation covers repeated safe events; an unsafe event first hides geometry and later safe events cannot resurrect it without fresh repair/full result.

Persistent additional state is one Boolean in DocumentChange; there is no per-line index/certificate array/global cache. Classification visits at most256 combined fragment characters. Coordinate lookup is one SDK logical mapping plus line metadata and is admitted only for a bounded physical prefix. These are input/work admission bounds, not measured wall-clock/allocation guarantees. Main should measure event classification and logical mapping separately at ordinary/tab/4096-boundary prefixes; no benchmark/timing was executed here.

Closing-minimum indentation edits usually start at C<=G and must hide. Non-whitespace/newline edits, >256 combined fragments, >4096 mapping prefixes, invalid pair/token/layout and missing geometry remain conservative. No nonanchor insertion-only extension was implemented. Runtime full analysis and immediate repair ordering, EDT publication/native revision, frame reentry, and ADR0001 genuinely affected-guide hiding remain unchanged.

## Added SDK contracts (implementation preparation)

The SDK fixture uses its existing direct EditorGuide with injected read-only results and scoped DocumentListener/CaretListener forwarding of actual DocumentChange.from(event) and caretMoved calls. It never replaces another owner's global registry factory. Driver separately exercises the production registry and event route. Headless activity is explicitly ACTIVE through the existing UI interface, not a real focus proof. Actual EditorTab/EditorUnindentSelection exercise logical columns 12→16→12 with spaces for three repetitions; every UI CONTENT reconciliation callback checks valid retained renderer, updated pair geometry/pixels and no repair. Actual event columns/deltas must be12/+4 and12/-4. A separate fixture begins with tab characters and checks actual tab-expanded logical columns 12→16→12 through repeated actions and inline whitespace. The IDE may emit mixed spaces/tabs, so exact fragment encoding is diagnostic rather than the geometry oracle. No synthetic boolean-only proof test substitutes for these action contracts.

Negative SDK scenarios cover closing minimum Tab, body outdent creating a new minimum, selection outdent across body+closing, newline mixed fragments,257-space change, a small event after a4097-character prefix, bracket token deletion and tab layout change. They require immediate hiding and the appropriate exact repair interest; token destruction must leave no repair target. Production is not forced to keep geometry when correctness cannot be proved. Existing reentry/rollback/pair-switch tests remain unchanged.

Same-turn callback/BufferedImage assertions prove presentation state, not absence of asynchronously visible flicker. No same-EDT remove/add gap is called visible flicker. Execution was main-owned; completed results and retained failures are recorded in verification-report.md. This agent changed only assigned DocumentChange/GuidePositionFallback/event capture/test sources and this note; no core/runtime/model/build/golden/threshold/commit/external work.
